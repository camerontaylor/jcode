1. **Upstream tags were pushed to the fork.** This repo has `push.followTags=true`, so the first branch push also sent upstream's `v1.0.0`, `v1.0.1` and `v1.0.2` tags to `origin`. Each started upstream's `Release` workflow, and all three runs were *skipped* by its repository guard. No fork release was created. The tags point at upstream's own commits. Decide whether to keep or delete them; I did not delete anything. `fork-release.yml` also triggers on `v*` tags, so later pushes should use `--no-follow-tags` (recorded in shared memory).
2. **TURN_STOP semantics in our drain** (`server/state.rs:660-705`). Upstream logs the terminal reason from the producer's events. Ours also observes the synthesized `Done`/`Error` for an aborted producer, so an aborted turn logs `reason=unknown` with request id `0`. Upstream would log `request=unknown`. Diagnostic only.
3. **`mobile_local.rs:93`**: the origin for phone-relayed prompts is `Relay`. If the TUI or ACP should treat these as the user's own prompts, switch to `Client`.
4. **`session_event_targets`** (`server/state.rs:416`, used by the cancel path in `client_processing.rs:605`) does not call `stream_batching::note_session_targets`. It only snapshots targets for `TurnStopped`, so batching state still comes from normal fanout. Low risk.
5. **ACP todo push.** Upstream daemons now advertise `Todos.pushes`. The fork's ACP router still polls `GetTodos`. This works, but could use pushes later.
6. **Flaky upstream test.** `tui::app::remote::tests::unfocused_redraw_warranted_tracks_live_activity` (`crates/jcode-tui/src/tui/app/remote_tests.rs:118`) failed in a 640-test filtered parallel run and passes alone. It reads process-global redraw and animation state. Neither it nor `redraw_schedule.rs` has fork changes.
7. **Workspace-wide clippy** (`cargo clippy --workspace --all-targets`, without `--all-features`) reports 4 deny-level errors. All are in upstream-owned files with no fork diff: `group_transfer_tests.rs:613`, `browser_size_tests.rs:74`, `mobile_runner_events_tests.rs:314`, `runtime_activity.rs:593`. The fork CI gate itself passes.
8. Many hunks were resolved by replaying `diff base..ours` onto upstream's new file. That is exact for the logic replayed, but upstream may have changed nearby behaviour in the same functions. The CI run on this head is the authority.
